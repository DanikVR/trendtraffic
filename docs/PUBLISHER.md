# Публикатор — постинг из Галереи в соцсети (Blotato)

> Статус: **Ф1–Ф5 реализованы** (Ф1 = app v2.1.4 в проде; Ф2–Ф5 = app v2.1.5, 2026-07-08).
> Дизайн-эталон: **/design/publisher-design.html** (самодостаточный HTML, обе темы, встроенный Geist).
> Живой макет-спека: https://claude.ai/code/artifact/ddf33d64-afc2-4eb9-b7f4-2441f37b00d6

## Что это

Вкладка «Публикатор» в Галерее (`/gallery?tab=publisher`): публикация роликов и фото
в 9 соцсетей — TikTok, Instagram, YouTube, X, Facebook, LinkedIn, Threads, Bluesky,
Pinterest — через **Blotato** (единый API вместо девяти OAuth-интеграций).

Функциональный референс — github.com/robertguss/social_post (планировщик X+LinkedIn):
его набор фич (композер, счётчики, расписание, ретраи, шаблоны, ИИ-подписи) переносится
на наши 9 платформ по фазам (см. «Дорожная карта»).

## Ключевые решения (юзер, 08.07.2026)

| # | Решение |
|---|---------|
| В1 | **BYO**: у каждого пользователя свой аккаунт my.blotato.com и свой API-ключ. Вводится в «Настройки → Ключи → Blotato», кнопка «Проверить» реально пингует API. Промежуточный вариант (white-label Late, наш сервисный ключ) рассматривался и отменён юзером в тот же день. |
| В2 | Доступ — **все платные тарифы** (Премиум/Энтерпрайз/триал): гейт `hasEnterpriseAccess` (как у Трендов). Наших затрат нет — тариф Blotato оплачивает клиент. |
| В3 | Ручная и автоматическая публикация сосуществуют через **цепочки в календаре** (Ф2/Ф4): ручная цепочка = серия готовых роликов по слотам; авто-цепочка = шаблон UGC генерит к слоту. |
| В4 | Композер — **полноэкранная студия** (как UGC-студия), не модалка. |
| В5 | **Плитки всех сетей** в Публикаторе; клик открывает **сразу нужную страницу кабинета Blotato** (Settings → Social Accounts). Подключить соцсети через API у Blotato нельзя — только их кабинет; пароли вводятся только в OAuth-окнах самих платформ. |
| — | Комментарии и директ — **план Б**: только если в будущем подключится Ayrshare Business ($599/мес за 30 профилей). Бонус: IG-комменты/директ есть и у Blotato — можно включить раньше без смены провайдера. |

## Как реализована Ф1

### Бэкенд — `apps/backend/src/modules/publisher/`

- **`blotato.ts`** — тонкий клиент: база `https://backend.blotato.com/v2`, заголовок
  `blotato-api-key`, таймауты + один ретрай на 429/502/503 (лимит Blotato — 30 постов/мин).
  Функции: `listAccounts`, `listSubaccounts` (страницы FB/LinkedIn, плейлисты YT),
  `listPinterestBoards`, `createPost` (now | `scheduledTime` UTC | `useNextFreeSlot`),
  `getPostStatus` (защитный парсинг — формат Get Post Status не прогонялся на живом сабмите),
  `cancelScheduled` (DELETE /schedules/:id).
- **`router.ts`** — JWT + гейт платных внутри роутера:
  - `GET /api/publisher/status` — есть ли ключ (фронт показывает онбординг);
  - `GET /api/publisher/accounts` — кэш 5 мин в памяти процесса, `?refresh=1`;
    401 от Blotato → 409 `bad_key` (фронт: «проверьте ключ»);
  - `GET /api/publisher/accounts/:id/subaccounts`, `GET /api/publisher/pinterest/boards`;
  - `POST /api/publisher/posts` — `{assetId|mediaUrl, text, mode: now|time|slot, scheduledAt?, targets[]}`;
    один вызов Blotato на каждый таргет с паузой 350 мс; ошибки per-таргет не валят остальные;
    медиа-URL абсолютизируется (`PUBLIC_BASE_URL`/host) — Blotato качает файл сам;
  - `GET /api/publisher/posts` — история + **ленивый синк**: до 8 сабмитов «в полёте» за запрос;
  - `POST /api/publisher/posts/:id/retry`, `DELETE /api/publisher/posts/:id` (отмена
    запланированного через Blotato / удаление записи из истории).
- **Обязательные поля платформ** собираются в `buildTarget()` с безопасными дефолтами:
  TikTok — privacyLevel `PUBLIC_TO_EVERYONE`, дуэты/ститчи/комменты вкл., `isAiGenerated: true`
  (честная метка — наши ролики сгенерированы; отключаемо в студии);
  YouTube — `title` (обязателен), `privacyStatus: public`, `shouldNotifySubscribers: true`.
  Facebook без `pageId` и Pinterest без `boardId` отбиваются ДО сабмита с понятной ошибкой.
- **Ключ** — запись `blotato` в `PROVIDERS` (`tenant_settings/provider_keys.ts`):
  шифрование AES-256-GCM уже было; «Проверить» = живой `GET /users/me/accounts`.
- **Миграция** — `publisher_posts`: 1 строка = 1 таргет (аккаунт×платформа), `group_id`
  связывает таргеты одной публикации; `submission_id/status/post_url/error`.
  Постоянная история — у Blotato окно списка ~7 дней.

### Фронт

- **`pages/publisher/PublisherTab.tsx`** — вкладка: онбординг без ключа (3 шага + кнопки
  «Открыть кабинет Blotato» / «Ввести ключ в Настройках» → `/settings/enterprise?section=openmontage`),
  плитки 9 сетей со статусами (✓ @handle / «Подключить →» — обе ведут в кабинет Blotato),
  стат-карточки (в очереди/опубликовано/ошибки), лента карточек (группировка по `group_id`,
  чипы статусов: ⏳ / ✓ со ссылкой на живой пост / ✗ с причиной / отменён; «Повторить» и
  «Отменить» — всегда видны), поллинг 8 с пока есть «в полёте». `PLATFORM_META`/`PlatformMark`
  экспортируются и переиспользуются студией.
- **`pages/publisher/PublisherStudio.tsx`** — полноэкранная студия: медиа из Галереи
  (единый `GalleryPicker`), текст со счётчиками лимитов по выбранным сетям
  (X 280 · Threads 500 · Bluesky 300 · IG/TikTok 2200 · LinkedIn 3000), аккаунты-тумблеры,
  платформенные опции (TikTok 6 обязательных + черновик; YouTube title/privacy/уведомить;
  IG Reel|Пост|Story; FB страница — сабаккаунты грузятся лениво, единственная подставляется
  сама; Pinterest доска + ссылка; LinkedIn от имени страницы; Threads кто отвечает),
  «Когда»: Сейчас | Дата и время (`datetime-local` → UTC ISO) | Следующий слот.
  Предвалидация: медиа обязательно для TikTok/IG/YT/Pinterest; результаты per-платформа;
  полный успех → автопереход в ленту Публикатора.
- **`GalleryPage.tsx`** — вкладка publisher → PublisherTab; зелёная кнопка «Опубликовать»
  (Send) в подвале карточек видео/фото — всегда видна (канон карточек); студия-оверлей.
- Мелочи: BottomTabBar «Скоро» → «Посты в соцсети»; BillingPage без «(скоро)»;
  `/settings/enterprise` понимает `?section=`.

## Грабли и ограничения Blotato (заложены в код)

- **Лимит 30 постов/мин** → пауза 350 мс между таргетами + ретрай на 429.
- **Окно списка постов ~7 дней** → постоянная история в `publisher_posts`.
- **Слоты расписания могут гейтиться тарифом**: живой зонд на ключе юзера получил
  `GET /v2/schedule/slots` → 401 при рабочем ключе. Режим «Следующий слот» в студии
  оставлен — если тариф не позволяет, Blotato вернёт ошибку, она отобразится per-таргет.
- **Аналитика** только X/IG/FB/Threads/Bluesky → для TikTok/YouTube мост в «Каналы» (TikHub) — Ф5.
- **Подключение соцсетей** — только кабинет my.blotato.com (API нет): плитки ведут туда.
- **Get Post Status** парсится защитно (`unknown` не считается ошибкой) — форму ответа
  подтвердить на первом живом сабмите.

## Ф2–Ф5 — как реализовано (app v2.1.5)

### Ф2 — слоты, календарь, ручные цепочки
- **Слоты «Моё расписание» — СВОИ** (`publisher_slots`: dow/hh/mm в UTC; UI показывает и
  принимает местное время, конверсия на фронте). Слоты Blotato НЕ используются — на живом
  ключе юзера они отдавали 401 (гейт тарифа), свои же работают у всех и нужны цепочкам.
  «Следующий слот» в студии = наш расчёт (`nextFreeSlotTimes`: кандидаты на 35 дней минус
  занятые ±60с — серии раскладываются на месяц вперёд, v2.2.55) → в Blotato уходит обычный
  `scheduledTime`. Сами слоты — недельная сетка: повторяются каждую неделю без ограничения срока.
- **Календарь** (саб-вкладка): неделя ‹›, запланированные посты чипами по дням; «перенести»
  (PATCH `/v2/schedules/:id` + строка) и «отменить». Значок 🔗 = пост цепочки.
- **Ручные цепочки**: мультивыбор в Галерее → зелёная «Опубликовать (N)» → форма серии
  (аккаунты, подпись ИИ/фикс) → все ролики раскладываются по свободным слотам СРАЗУ
  (`publisher_chains` kind=manual + posts.chain_id). Не хватает слотов → честная ошибка.

### Ф3 — Пост-движок, версии текста, треды, шаблоны
- `POST /api/publisher/ai-caption` — Claude (ключ тенанта «ИИ-режиссёр», модель режиссёра):
  A/B-варианты `{base, hashtags[], platforms{...}, youtubeTitle}`; контекст = название +
  TrendDNA ролика (hook/whyItWorks/keywords/сценарий), если есть разбор. В студии — панель ✦
  (тона: вовлекающий/экспертный/продающий), «Применить» раскладывает текст + overrides + YT-title.
  Хэштеги «актуальные из TikHub-скана» — TODO следующего витка (дорогой вызов в каптионе).
- **Версии текста**: вкладки «Все + per-платформа ✎» → `textOverride` per target.
- **Раскладка по сетям — одна точка**: `targetsWithCaptions()` вешает `textOverride` на каждый
  таргет через `captionForPlatform()` (свой текст сети → фолбэк на `base`; хэштеги с лимитом
  YT 5 / X+Bluesky 3 / прочие 8; LinkedIn без тегов; уже стоящие в тексте теги не дублируются;
  всё режется по `TEXT_LIMITS` сети). Ею пользуются ОБА вида цепочек — до v2.6.22 они слали
  один `base` во все сети, и персонализация Пост-движка терялась (черновики работали верно).
- **Тред** (X/Threads/Bluesky): textarea, пустая строка = следующий пост треда →
  `content.additionalPosts` (форма поля предположена по докам — проверить на живом треде).
- **Шаблоны** (`publisher_templates`): вставка в текст + «Сохранить текущий».

### «Обязательный текст» (подпись тенанта)
- Таблица `publisher_settings` (`tenant_id` PK, `signature`), ручки `GET/PUT /api/publisher/settings`.
  Поле живёт в композере под текстом поста, сохраняется на blur.
- Дописывает **бэкенд** — одной правкой закрыты ВСЕ пути: композер, массовые черновики,
  ручные и авто-цепочки, ручной архив. Точки вызова `withSignature`: `submitPost` (rowText),
  `createDrafts`, `createManualPosts`.
- ⚠️ `withSignature` **идемпотентна**: путь черновика двухшаговый (`createDrafts` пишет текст →
  `publishDrafts` отправляет `row.text` как есть), без проверки `endsWith` подпись удвоилась бы.
- При нехватке лимита сети режется ОСНОВНОЙ текст, подпись остаётся целой.
- Счётчики символов в Студии считают текст вместе с подписью — иначе они врут о том,
  что реально уйдёт в сеть.

### Ф6 — ручной архив (публикация руками, без Blotato)
- **Зачем**: соцсети можно не подключать к Blotato вовсе — сервис тогда работает как
  правильно разложенный архив: ролик + готовое описание под каждую сеть + дата в календаре.
- **Статус `'manual'`**: строка живёт ТОЛЬКО у нас, в Blotato не уходит никогда.
  `account_id = 'manual:<сеть>'` (колонка NOT NULL, а подключённого аккаунта нет),
  `submission_id` всегда NULL, `scheduled_at` = дата в календаре (может быть пустой).
  Слот-занятость (`nextFreeSlotTimes` смотрит scheduled/submitted), статус-синк и
  авторетраи такие строки НЕ видят. Миграция не понадобилась: `status` — свободный VARCHAR.
  ⚠️ Добавляя статус, добавляйте его и в `FOLDER_OF` (PublisherTab.tsx) — иначе строка
  молча пропадает из ленты.
- `POST /api/publisher/manual` — `{items[], platforms[], ai?, tone?, language?, scheduledAt?,
  texts?, titles?}` → `202 {jobId}` (прогресс — через общий `/drafts/bulk/status`).
  `texts` = готовые тексты из Студии: что задано там, ИИ не перезаписывает и не оплачивает;
  пустые сети дописывает Пост-движок.
- `PATCH /api/publisher/manual/:id` — `{text?, title?, scheduledAt?, wholeGroup?}`.
  `wholeGroup` двигает весь ролик: сети одного поста живут одной датой.
- **Композер**: переключатель «Через Blotato / Вручную»; в ручном режиме — плитки всех
  9 сетей без требования аккаунта.
- **Раскрытый пост** (`PublisherPostModal.tsx`): плеер, вкладки сетей, правка текста и
  заголовка YouTube, «Скачать видео» (`downloadMedia`), «Скачать описание» (.txt по сети,
  у YouTube с заголовком первой строкой), «Копировать», дата, удаление. Открывается
  из ленты (обложка/заголовок) и из календаря (клик по дате).
- **Календарь** показывает `scheduled` И `manual` (значок «M»); перенос ручного поста
  идёт своим маршрутом, а не через Blotato.

### Ф4 — авто-цепочки (замыкание конвейера трендов)
- `publisher_chains` kind=auto: тик раз в минуту берёт **свежий НЕопубликованный ролик
  автопилота** (папка `auto-ugc` — их производит конвейер тренд→UGC) → подпись Пост-движком
  (фолбэк без ИИ: название + ключевые слова ДНК — цепочка не встаёт без ключа Claude) →
  ближайший свободный слот. Страховки: dailyCap (постов/день), **автопауза после 3 фейлов
  подряд** (fail_streak + last_error видны в UI), тумблер активна/пауза.
- Генерацию видео Публикатор НЕ запускает — ролики уже производит автопилот трендов
  (hook buildFromTemplate не понадобился: связь через папку auto-ugc).
- **Формат-маршрутизация (v2.2.55)**: у авто-цепочки есть фильтр «Формат» (`format_filter`:
  9x16/16x9/1x1/4x5, NULL = любой) — берёт из «Авто» только ролики своего формата.
  UGC-сборка пишет формат каждого ассета в `media_assets.ugc_format`. Рецепт «9:16 в TikTok,
  16:9 в YouTube»: шаблон UGC собирает оба формата → две авто-цепочки с разными фильтрами;
  их наборы файлов не пересекаются, конкуренции за ролики нет. Ролики, собранные ДО v2.2.55
  (`ugc_format` = NULL), видят только цепочки без фильтра.

### Ф5 — петля данных
- **Авторетраи**: транзиентные фейлы (сеть/429/5xx) получают `next_retry_at` (2→4→8 мин,
  до 3 попыток); тик пере-отправляет ≤5 строк/мин; в ленте бейдж «повтор HH:MM».
  Валидационные ошибки (нет pageId/boardId) не ретраятся.
- **Фоновый статус-синк**: каждый 5-й тик — Get Post Status по тенантам с «в полёте»,
  даже когда лента закрыта (плюс прежний ленивый синк при открытой ленте).
- **Аналитика** (саб-вкладка): `GET /v2/analytics` Blotato (X/IG/FB/Threads/Bluesky),
  защитный парсинг полей (viewsCount/likesCount/…); TikTok/YouTube — «Тренды → Каналы»
  (TikHub). Мост «пост → Каналы» не делался: вотчлист Каналов — по каналам, не по постам.
- **Комменты/директ — НЕ делались**: план Б, только если подключится Ayrshare Business
  (решение юзера 08.07).
- Планировщик: `modules/publisher/scheduler.ts` (setInterval 60с, guard, старт в server.ts).
