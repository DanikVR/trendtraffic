# Публикатор — постинг из Галереи в соцсети (Blotato)

> Статус: **Ф1 реализована** (app v2.1.3, ветка `feat/publisher`, 2026-07-08).
> Дизайн-эталон: **/design/publisher-design.html** (самодостаточный HTML, обе темы, встроенный Geist).
> Живой макет-спека: https://claude.ai/code/artifact/ddf33d64-afc2-4eb9-b7f4-2441f37b00d6

## Что это

Вкладка «Публикатор» в Галерее (`/gallery?tab=publisher`): публикация роликов и фото
в 9 соцсетей — TikTok, Instagram, YouTube, X, Facebook, LinkedIn, Threads, Bluesky,
Pinterest — через **Blotato** (единый API вместо девяти OAuth-интеграций).

Функциональный референс — github.com/robertguss/social_post (планировщик X+LinkedIn):
его набор фич (композер, счётчики, расписание, ретраи, шаблоны, ИИ-подписи) переносится
на наши 9 платформ по фазам (см. «Дорожная карта»).

## Ключевые решения (юзер, 08.07.2026)

| # | Решение |
|---|---------|
| В1 | **BYO**: у каждого пользователя свой аккаунт my.blotato.com и свой API-ключ. Вводится в «Настройки → Ключи → Blotato», кнопка «Проверить» реально пингует API. Промежуточный вариант (white-label Late, наш сервисный ключ) рассматривался и отменён юзером в тот же день. |
| В2 | Доступ — **все платные тарифы** (Премиум/Энтерпрайз/триал): гейт `hasEnterpriseAccess` (как у Трендов). Наших затрат нет — тариф Blotato оплачивает клиент. |
| В3 | Ручная и автоматическая публикация сосуществуют через **цепочки в календаре** (Ф2/Ф4): ручная цепочка = серия готовых роликов по слотам; авто-цепочка = шаблон UGC генерит к слоту. |
| В4 | Композер — **полноэкранная студия** (как UGC-студия), не модалка. |
| В5 | **Плитки всех сетей** в Публикаторе; клик открывает **сразу нужную страницу кабинета Blotato** (Settings → Social Accounts). Подключить соцсети через API у Blotato нельзя — только их кабинет; пароли вводятся только в OAuth-окнах самих платформ. |
| — | Комментарии и директ — **план Б**: только если в будущем подключится Ayrshare Business ($599/мес за 30 профилей). Бонус: IG-комменты/директ есть и у Blotato — можно включить раньше без смены провайдера. |

## Как реализована Ф1

### Бэкенд — `apps/backend/src/modules/publisher/`

- **`blotato.ts`** — тонкий клиент: база `https://backend.blotato.com/v2`, заголовок
  `blotato-api-key`, таймауты + один ретрай на 429/502/503 (лимит Blotato — 30 постов/мин).
  Функции: `listAccounts`, `listSubaccounts` (страницы FB/LinkedIn, плейлисты YT),
  `listPinterestBoards`, `createPost` (now | `scheduledTime` UTC | `useNextFreeSlot`),
  `getPostStatus` (защитный парсинг — формат Get Post Status не прогонялся на живом сабмите),
  `cancelScheduled` (DELETE /schedules/:id).
- **`router.ts`** — JWT + гейт платных внутри роутера:
  - `GET /api/publisher/status` — есть ли ключ (фронт показывает онбординг);
  - `GET /api/publisher/accounts` — кэш 5 мин в памяти процесса, `?refresh=1`;
    401 от Blotato → 409 `bad_key` (фронт: «проверьте ключ»);
  - `GET /api/publisher/accounts/:id/subaccounts`, `GET /api/publisher/pinterest/boards`;
  - `POST /api/publisher/posts` — `{assetId|mediaUrl, text, mode: now|time|slot, scheduledAt?, targets[]}`;
    один вызов Blotato на каждый таргет с паузой 350 мс; ошибки per-таргет не валят остальные;
    медиа-URL абсолютизируется (`PUBLIC_BASE_URL`/host) — Blotato качает файл сам;
  - `GET /api/publisher/posts` — история + **ленивый синк**: до 8 сабмитов «в полёте» за запрос;
  - `POST /api/publisher/posts/:id/retry`, `DELETE /api/publisher/posts/:id` (отмена
    запланированного через Blotato / удаление записи из истории).
- **Обязательные поля платформ** собираются в `buildTarget()` с безопасными дефолтами:
  TikTok — privacyLevel `PUBLIC_TO_EVERYONE`, дуэты/ститчи/комменты вкл., `isAiGenerated: true`
  (честная метка — наши ролики сгенерированы; отключаемо в студии);
  YouTube — `title` (обязателен), `privacyStatus: public`, `shouldNotifySubscribers: true`.
  Facebook без `pageId` и Pinterest без `boardId` отбиваются ДО сабмита с понятной ошибкой.
- **Ключ** — запись `blotato` в `PROVIDERS` (`tenant_settings/provider_keys.ts`):
  шифрование AES-256-GCM уже было; «Проверить» = живой `GET /users/me/accounts`.
- **Миграция** — `publisher_posts`: 1 строка = 1 таргет (аккаунт×платформа), `group_id`
  связывает таргеты одной публикации; `submission_id/status/post_url/error`.
  Постоянная история — у Blotato окно списка ~7 дней.

### Фронт

- **`pages/publisher/PublisherTab.tsx`** — вкладка: онбординг без ключа (3 шага + кнопки
  «Открыть кабинет Blotato» / «Ввести ключ в Настройках» → `/settings/enterprise?section=openmontage`),
  плитки 9 сетей со статусами (✓ @handle / «Подключить →» — обе ведут в кабинет Blotato),
  стат-карточки (в очереди/опубликовано/ошибки), лента карточек (группировка по `group_id`,
  чипы статусов: ⏳ / ✓ со ссылкой на живой пост / ✗ с причиной / отменён; «Повторить» и
  «Отменить» — всегда видны), поллинг 8 с пока есть «в полёте». `PLATFORM_META`/`PlatformMark`
  экспортируются и переиспользуются студией.
- **`pages/publisher/PublisherStudio.tsx`** — полноэкранная студия: медиа из Галереи
  (единый `GalleryPicker`), текст со счётчиками лимитов по выбранным сетям
  (X 280 · Threads 500 · Bluesky 300 · IG/TikTok 2200 · LinkedIn 3000), аккаунты-тумблеры,
  платформенные опции (TikTok 6 обязательных + черновик; YouTube title/privacy/уведомить;
  IG Reel|Пост|Story; FB страница — сабаккаунты грузятся лениво, единственная подставляется
  сама; Pinterest доска + ссылка; LinkedIn от имени страницы; Threads кто отвечает),
  «Когда»: Сейчас | Дата и время (`datetime-local` → UTC ISO) | Следующий слот.
  Предвалидация: медиа обязательно для TikTok/IG/YT/Pinterest; результаты per-платформа;
  полный успех → автопереход в ленту Публикатора.
- **`GalleryPage.tsx`** — вкладка publisher → PublisherTab; зелёная кнопка «Опубликовать»
  (Send) в подвале карточек видео/фото — всегда видна (канон карточек); студия-оверлей.
- Мелочи: BottomTabBar «Скоро» → «Посты в соцсети»; BillingPage без «(скоро)»;
  `/settings/enterprise` понимает `?section=`.

## Грабли и ограничения Blotato (заложены в код)

- **Лимит 30 постов/мин** → пауза 350 мс между таргетами + ретрай на 429.
- **Окно списка постов ~7 дней** → постоянная история в `publisher_posts`.
- **Слоты расписания могут гейтиться тарифом**: живой зонд на ключе юзера получил
  `GET /v2/schedule/slots` → 401 при рабочем ключе. Режим «Следующий слот» в студии
  оставлен — если тариф не позволяет, Blotato вернёт ошибку, она отобразится per-таргет.
- **Аналитика** только X/IG/FB/Threads/Bluesky → для TikTok/YouTube мост в «Каналы» (TikHub) — Ф5.
- **Подключение соцсетей** — только кабинет my.blotato.com (API нет): плитки ведут туда.
- **Get Post Status** парсится защитно (`unknown` не считается ошибкой) — форму ответа
  подтвердить на первом живом сабмите.

## Дорожная карта (после Ф1)

- **Ф2** — календарь + слоты (нативные Blotato по тарифу, фолбэк свои) + ручные цепочки.
- **Ф3** — Пост-движок: Claude-подписи per-платформа на контексте TrendDNA + покадрового
  анализа + бренд-кита; хэштеги трёх слоёв (бренд + ниша + актуальные из TikHub-скана); A/B;
  переопределения текста per-аккаунт; треды (additionalPosts); пакетная публикация мультивыбора.
- **Ф4** — авто-цепочки: шаблон UGC с автопубликацией → сборка за ~2 ч до слота →
  авто-подпись → `scheduledTime` = слот (хук buildFromTemplate — место Ayrshare занимает Blotato).
- **Ф5** — статус-тик вне открытой ленты, авторетраи с бэкоффом, «Аналитика» + TikHub-мост,
  комментарии/директ (план Б: Ayrshare Business по решению юзера, или IG-эндпоинты Blotato).
