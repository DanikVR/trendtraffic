# TrendTraffic — UGC / Аватары: архитектура, интеграции, эксплуатация

Блок **«UGC / Аватары»** в редакторе сценария TrendFlow (`MontageEditor.tsx`, облако `ugc`).
Превращает **аватар + скрипт/запись + видео** в вертикальные (или горизонтальные) короткие ролики.
Готовое падает в **Галерею** (папка `reference`).

Документ описывает всё, что не разбросано по коду: три режима сборки, два движка аватара, внешние
интеграции, экономику, форматы вывода и как это проверять.

---

## 0. Как это устроено (за 60 секунд)

Панель UGC даёт выбрать **источник аватара** и **как получить голос/скрипт**, затем «Собрать UGC»
запускает фоновую джобу `/api/render/ugc/build` → поллинг статуса → готовые ролики в Галерею.

**Два движка аватара** (НЕ смешиваются):
- **«Своё фото» → HeyGen** (Avatar IV/III) — облачно, лицо оживляется из фото. Синхронизирует губы сам.
- **«Коллекция» → SpatialReal** — realtime-движок на домашнем ПК (сервис `sr-capture`), захват кадров
  с альфой. Требует запущенного `sr-capture` (Tailscale). Для HeyGen-путей **не нужен**.

**Три режима сборки** (взаимоисключающие, ветвление в `/ugc/build`):
1. **Обычный** — один аватар говорит скрипт, склейка с одним видео (блок сверху/снизу или PiP).
2. **Удержание** (`spec.retention`) — «переключения техник» под одну дорожку: пресеты + LLM-разметка
   дорогого Avatar IV; батч (N видео → N роликов, аватар рендерится 1 раз).
3. **Диалоги** (`spec.dialogue`) — два собеседника, каждый своим лицом; LLM-режиссура плана показа.

**Формат вывода** — 9:16 / 16:9 / оба (аватар рендерится 1 раз, склейка на каждый формат).

## 1. Внешние интеграции (ключи — per-tenant в Настройки → Генерация)

| Провайдер | id ключа | Зачем в UGC |
|---|---|---|
| **HeyGen** | `heygen` | Оживление фото (Avatar IV/III): talking_photo → video. Все режимы «Своё фото» + удержание + диалоги. |
| **SpatialReal** | `spatialreal` | Realtime-аватары «Коллекция» (библиотека 20 шт. + оживление). Через `sr-capture`. |
| **ElevenLabs** | `elevenlabs` | Озвучка скрипта (TTS) по полу, когда голос НЕ из записи. |
| **Gemini** | `google_omni`/`google` (эффективный) | Диаризация записи на 2 голоса (`diarizeWithGemini`) + генерация коллекции аватаров (Nano Banana). |
| **Anthropic Claude** | `anthropic` (fallback env) | ИИ-режиссура: генерация диалога, разметка IV удержания (`tagUgcRetention`), план диалога (`directDialogue`). |
| **HuggingFace** | `hf` | Фолбэк-диаризация на рендер-воркере (pyannote), если Gemini недоступен. |

**Ключевая гоча SpatialReal:** их API отвечает HTTP **200 даже на ошибки** — реальный статус в
`body.errors[].status`. Работает **только** session-token → Bearer (X-Api-Key напрямую = 401).

**HeyGen для talking_photo** синхронизирует губы сам (детекция задержки не нужна, в отличие от
SpatialReal). Фон фото по умолчанию **сохраняется** (мы не задаём `background`), кроме опции вырезки (§6).

## 2. Голос и скрипт (общий вход всех режимов)

`spec.source`:
- **`gen`** — Claude генерит скрипт по брифу (`generatePodcastDialogue`), затем озвучка ElevenLabs (`elevenTTS`).
- **`diarize`** — «Разобрать запись»: `POST /api/render/podcast/diarize` (Gemini → фолбэк воркер) →
  реплики `[{speaker:'A'|'B', start, end, text}]`. **Запись = мастер-голос** (для диалогов оба голоса).

Реплики редактируются в общем компоненте **`DialogueTimeline`** (тот же, что в Подкасте/Комментаторе):
двухдорожечный таймлайн A/B, перетаскивание, резка/склейка, привязка медиа к реплике, воспроизведение.

**Важно:** обычный UGC схлопывает все реплики в спикера A (один аватар). Режим «Диалоги» **сохраняет
A/B** (`ugcRunDiarize`, флаг `keepAB`).

## 3. Режим «Удержание» (v1.6.122/128)

Идея: под ОДНУ непрерывную дорожку голоса кадр каждые несколько секунд меняет технику показа, дорогой
Avatar IV — только на пики. Только HeyGen «Своё фото».

**Пресеты** (`retention.ts` → `RETENTION_PRESETS`): Эконом (ivMax 2) / Баланс (3) / Премиум (4). Каждый —
ритм сегментов (% длины + базовая раскладка/движок).

**Пайплайн** (ветка `spec.retention.preset && isPhoto` в `/ugc/build`):
1. Голос (запись или ElevenLabs) → длина `D` (`mediaDuration`).
2. `planWindows(lines, preset, D)` — %-окна, границы притянуты к паузам между фразами (`snapToGap`).
3. `tagUgcRetention` (Claude) — какие окна поднять на IV (крючок/действие/призыв ≤ ivMax); фолбэк —
   эвристика `planRetention` (регексы **БЕЗ `\b`** — в JS `\b` не работает с кириллицей).
4. `uploadTalkingPhoto` **один раз** → посегментный `submitTalkingPhotoVideo` (useIV по движку сегмента),
   аудио — срез записи под сегмент (`sliceAudioToRenders`, публичный URL для HeyGen).
5. Поллинг всех сегментов → `composeRetentionVideo` по **каждому** B-roll.

**Батч:** `spec.retention.brolls` = N видео из Галереи → N роликов; аватар переиспользуется ⇒ цена
HeyGen как за один ролик (меняется только фон).

**Раскладки сегмента** (`RetComposeSeg.layout`): `closeup` (крупный план) / `split` (аватар+видео
блоком) / `broll` (только видео, лица нет = $0) / `pip` (аватар маленьким поверх видео).

## 4. Режим «Диалоги» (v1.6.128)

Два собеседника, каждый говорит своим лицом (HeyGen). Требует «Своё фото» + разбор записи двух голосов.

**Вход:** два фото (`photoUrl` = Спикер A, `photoBUrl` = Спикер B), запись (diarize), вовлечённость
`dialogueEngagement` (eco/bal/dyn).

**Планировщик** `dialogue.ts` → `planDialogue(lines, engagement)`:
- нормализация (сортировка по времени, срез наложений), склейка соседних реплик одного спикера без
  медиа в один сегмент (экономия рендеров);
- сегменты тайлят весь таймлайн без дыр;
- **растяжка медиа** (§5) → hold-сегмент + сдвиг последующих реплик;
- бюджеты `dlgPreset(engagement, faceCount)` = ivMax + twoshotMax.

**LLM-режиссура** `directDialogue` (Claude): per-turn `engine` (iv/iii), `twoshot` (оба в кадре),
`mediaLayout` (только для реплик с показом «Авто»). Фолбэк — эвристика `scoreDialogueHeuristic`.
`applyDlgBudget` поднимает top-N в IV / two-shot в пределах бюджета.

**Рендер** (ветка `spec.dialogue.enabled`):
1. Запись → мастер-голос; два фото → два `talking_photo` (tpA, tpB).
2. Лицевые сегменты (кроме media-full/hold) → `submitTalkingPhotoVideo` (talking_photo своего спикера,
   аудио = срез записи под окно). Two-shot **не** плодит рендер: второе лицо = **статичное фото** реакции.
3. `buildDialogueVoice` — непрерывная мастер-дорожка: срез записи (речь, добита тишиной до длины
   сегмента) + звук видео на держании (иначе тишина); каждый кусок форсится `apad + -t` ⇒ сумма = видео,
   губы не плывут.
4. `composeDialogueVideo` по каждому формату.

**Раскладки** (`DlgLayout`): `closeup` / `twoshot` (оба) / `media-full` / `media-bg-left` / `media-bg-right`
(медиа во весь кадр + говорящий маленьким сбоку) / `media-split` (медиа + лицо поровну).

## 5. Медиа реплики: аспект и растяжка

Медиа (фото/видео) привязывается к реплике в `DialogueTimeline`. В режиме «Диалоги» у реплики с медиа
появляются контролы **«Показ»** и **«Держать медиа»**.

**Аспект (важное правило TikTok):** композитор кладёт медиа функцией `placeFilter`:
- аспект близок к целевому кадру → **cover** (заполнить, кроп);
- иначе → **центр + размытый фон** (bg = cover+blur, fg = fit-inside по центру). Работает в **обе**
  стороны: 16:9-медиа в 9:16-кадре И 9:16-медиа в 16:9-кадре.

**Растяжка (v1.6.128):** «Держать медиа N сек». При загрузке **видео** из Галереи `holdSec` авто-ставится
= длине видео (`probeMediaDuration` на фронте) — покажется целиком. Если `holdSec` > длины реплики:
после речи медиа держится ещё `holdSec − реплика` сек (hold-сегмент, лица нет = $0), а **все
последующие реплики сдвигаются** на эту разницу; мастер-голос сплайсится, следующая речь не наложится.

## 6. Опциональная вырезка фона аватара (v1.6.132)

Тумблер **«Вырезать фон аватара»** (только режим «Диалоги», раскладка «фон + лицо сбоку»).

Раньше в `media-bg-left/right` аватар клался непрозрачным прямоугольником со своим фоном. С вырезкой:
- `submitTalkingPhotoVideo({ bgColor: '#00FF00' })` — HeyGen матирует talking_photo на **зелёный**
  (`video_input.background` type:color);
- `composeDialogueVideo` делает **chroma-key + despill** (`DlgComposeSeg.avatarChroma`, тот же паттерн,
  что студийные головы) → чистый силуэт человека поверх медиа.

Действует **только** для media-bg (closeup/two-shot/split — фон = сцена, не трогаем).

**Безопасный фолбэк:** если HeyGen проигнорит фон (оставит свой) → зелёного нет → chromakey ничего не
режет = как раньше (бокс), без вреда. ⚠️ Honorит ли HeyGen `background` для talking_photo — подтвердит
только живой прогон на ключе клиента. Решение по бэкенду вырезки: НЕ render-worker RVM (не хотим
привязку к домашнему GPU) и НЕ fal.ai (нет кода) — а зелёнка HeyGen + chromakey (self-contained, cloud).

## 7. Формат вывода 9:16 / 16:9 / оба (v1.6.134)

Раньше весь UGC был жёстко 9:16 (1080×1920). Теперь селектор **«Формат вывода»** (`spec.formats`):
`9:16` / `16:9` / `Оба`. `UGC_FORMATS`: 9x16 = 1080×1920, 16x9 = 1920×1080.

Все **три** композитора (`composeUgc`, `composeRetentionVideo`, `composeDialogueVideo`) получили параметр
`dims` и стали **ориентационными** (общие помощники `orientCells` + `placeFilter`):
- разложение двух элементов: портрет → верх/низ (**vstack**), ландшафт → лево/право (**hstack**);
- портретный аватар в ландшафтном кадре и любое медиа не по формату → центр + размытый фон.

Роутер: **все** ветки `/ugc/build` гоняют склейку на каждый формат из `spec.formats`, аватар HeyGen
рендерится **один раз** ⇒ «Оба» = цена как за один ролик (та же логика, что батч). `total = brolls × formats`.
Готовые файлы в Галерее с суффиксами `· 9:16` / `· 16:9`.

## 8. Экономика движка

| Что | Стоит |
|---|---|
| Avatar IV (HeyGen) | ~$4/мин (20 кредитов) — только на пики (крючок/действие/призыв/эмоция) |
| Avatar III (HeyGen) | ~$1/мин (3 кредита) — связки, обычные реплики |
| Сегмент только медиа/видео (лица нет) | **$0** |
| Реакция во two-shot (статичное фото) | **$0** |
| Держание медиа (hold) | **$0** и ещё удлиняет ролик |
| Батч N видео (удержание) | цена как за **1** ролик (аватар 1 раз) |
| «Оба» формата | цена как за **1** ролик (аватар 1 раз) |

Ориентир: ролик 1.5 мин на «Балансе» ≈ **$2–3**.

## 11. Как проверять (E2E)

**Версия:** в углу страницы `v1.6.134+`. Ветка разработки — `feat/ugc-avatar-grid`; деплой через
worktree от origin/main + `vps-redeploy.sh` (web-VPS; воркеры HeyGen — облачные).

**UI (бесплатно):** блок UGC → «Своё фото» → тумблер «Диалоги» → появляются фото B / вовлечённость /
«Вырезать фон»; блок «Формат вывода»; разбор записи двух голосов пишет «(два голоса A/B)»; у реплики с
медиа — «Показ» + «Держать медиа».

**Живой рендер (тратит кредиты HeyGen ~$2–3):** ключ HeyGen → два фото → разбор записи → (опц. медиа/
вырезка) → формат → «Собрать UGC» → ролики в Галерею.

**Проверить в результате:** спикеры говорят своим лицом; two-shot/врезки где решил Claude; 16:9-медиа
полосой по центру; растянутое медиа сдвинуло следующую реплику; вырезка = силуэт без прямоугольника;
«Оба» = два файла (`· 9:16`, `· 16:9`).

## 12. Статус проверки и ограничения

**Проверено синтетикой (ffmpeg, без ключей):** планировщики диалога/удержания; `composeDialogueVideo`
(6 раскладок, растяжка +Nс, длина = голосу); вырезка фона (зелёное→медиа, человек остался); все три
композитора × оба формата (верные размеры, ландшафтный hstack не падает).

**НЕ проверено вживую (нужен ключ клиента + кредиты):**
- реальный HeyGen-рендер диалога/удержания;
- honorит ли HeyGen `background:#00FF00` для talking_photo (иначе вырезка = как бокс, без вреда).

**Ограничения:**
- Диалог требует записи двух голосов (diarize) — генерённый скрипт для диалога не годится (нужны таймкоды).
- Перекрывающиеся (наложенные) реплики срезаются до последовательных.
- SpatialReal-путь требует запущенного `sr-capture` (домашний ПК); HeyGen-пути — полностью облачные.
- ⚠️ `sr-capture` автозапуск не прописан — после ребута ПК поднимать вручную.

**На будущее:** живой E2E на ключе клиента; EchoMimic-путь для своих фото в «Коллекции»; вырезка фона
для других раскладок/режимов при запросе.
